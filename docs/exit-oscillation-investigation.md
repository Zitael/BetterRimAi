# Exit oscillation investigation

The previous real-game log available on this machine predates Threat Safety v2: it contains the removed `cancel-scheduled`/`cancel-consumed` messages and does not identify the WorkGiver responsible for the v2 reproduction. The code-level loop is reproducible: a Touch work target can pass the safe-side exemption, but vanilla or another mod may choose an exposed interaction path. The v2 guard recorded only `Pawn_PathFollower.Destination`, which can differ from the `Thing`/cell passed to the next WorkGiver scan. Even when those cells matched, the safe-side Touch exemption ran before the observed-route lookup. The same job could therefore be selected again after cancellation.

The guard now records the path destination and the exterior targets of its current Job in the existing map snapshot. Observed actual-route evidence is checked before the theoretical Touch exemption. It remains tied to the danger cell and disappears on snapshot refresh when that cell is no longer dangerous. No time-only cooldown or JobDef-wide ban was added. `ThreatAwarePendingCancellation` remains solely to avoid ending a job from inside `TryEnterNextPathCell`.

When **Debug threat decisions** is enabled, a pawn that reaches the exceptional guard gets a bounded `[BetterRimAI][trace]` sequence in `Player.log`: the last completed WorkGiver/ThinkNode policy result, the final `StartJob`, JobDef/giver and target A/B/C with protected/outside classification, path destination, threat and danger cell, deferred cancellation, then the next selected job and rejected candidates. Logging is limited to three guard events and 24 lines per pawn in a 360-tick focus window. Normal candidate checks do not format trace messages. A one-time `selected-pawn inspect status rendered` line confirms whether the pawn inspect UI hook ran.

RimWorld's `InspectPaneFiller.DrawInspectStringFor(ISelectable, Rect)` calls `ISelectable.GetInspectString`; the `Pawn` interface implementation resolves to `Pawn.GetInspectString`. The UI hook prepends an always-present BetterRimAI status, so it is visible ahead of long vanilla inspect text. A headless Harmony/interface regression test verifies that dispatch; only a manual in-game playtest can confirm the final rendered layout with the user's mod list.

Manual reproduction: load the save with Threat-aware outdoor work and Debug threat decisions enabled; keep one pawn inside with dangerous exterior work and safe indoor work, then let it choose autonomously. Select the pawn before and during the attempted exit. Inspect the top of its information pane and collect the bounded `[BetterRimAI][trace]` lines from `Player.log`. Check for a sequence of `policy`, `StartJob`, `path guard`, `deferred cancellation`, and `next job started`. If no status appears, check whether the one-time inspect-rendered line exists; its absence points to UI dispatch or Harmony patching rather than merely an expired decision record. Repeat with an exterior wall repair from a safe-side Touch cell, and after the threat disappears to confirm that work resumes.
